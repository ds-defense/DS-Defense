# Contributing to DS Defense

Thank you for contributing to DS Defense.

This project is currently in an early coordination phase. Our priority is to make it easy for original authors, maintainers, researchers, and contributors to identify their work and participate directly.

You do not need to make a large contribution to participate.

A useful contribution may be as simple as:

- adding a missing project;
- correcting an attribution;
- identifying an original author;
- providing the correct license;
- linking to an authoritative repository;
- improving documentation;
- submitting code you are authorized to contribute.

## Before contributing

Please consider the following four questions:

1. **What project, component, research, or implementation are you contributing?**
2. **What is your relationship to the work?**
3. **What license or permission applies to the contribution?**
4. **Would you like to help maintain this component going forward?**

These questions help us preserve attribution and avoid accidentally redistributing work without permission.

## Types of contributions

### 1. Add a project

If you know of a relevant project that is missing, you can add it to `SOURCES.md`.

Please include, where known:

```text
Project name:
Repository / URL:
Original author(s):
Current maintainer(s):
License:
Relationship to DS Defense:
Your relationship to the project:
Additional notes:
```

If you do not know all of this information, incomplete entries are still welcome.

Mark unknown fields as:

```text
Unknown / To be confirmed
```

### 2. Claim or identify your work

If you are an original author or maintainer of a project already listed here, please open a Pull Request, Issue, or Discussion.

You may:

- confirm authorship;
- correct attribution;
- update the project description;
- provide the authoritative repository;
- clarify licensing;
- request that your project be linked rather than copied;
- volunteer to maintain the relevant entry or component.

### 3. Contribute code

Before contributing existing code, please confirm that you have the right to submit it.

Please tell us whether the code is:

- your original work;
- work you are authorized to contribute;
- already distributed under a compatible open-source license.

If the code originates from another repository, include a link to the original source and its license.

Please do not submit third-party code whose redistribution status is unclear.

A link to the original project is preferable until permission is confirmed.

### 4. Improve documentation

Documentation contributions are very welcome.

Examples include:

- architecture explanations;
- setup instructions;
- project comparisons;
- research references;
- terminology;
- examples;
- contributor guides;
- project history.

Where documentation describes someone else's work, please link to the original source whenever possible.

## Pull Request checklist

A Pull Request does not need to be large.

Before submitting, please check:

- [ ] I described what this contribution adds or changes.
- [ ] I identified the original source where applicable.
- [ ] I provided attribution where applicable.
- [ ] I identified the relevant license or marked it as unknown.
- [ ] I am authorized to submit any code included in this Pull Request.
- [ ] I have not intentionally removed existing attribution or licensing information.

## Suggested Pull Request description

You can use the following template:

```text
## What does this PR add or change?

Describe the contribution.

## Related project

Project:
Repository:
Original author(s):

## My relationship to the work

Choose or explain:

- Original author
- Maintainer
- Contributor
- Researcher
- Community member
- Other

## License / permission

License:

If unknown, write:
Unknown / To be confirmed

## Maintenance

Would you like to help maintain this component?

Yes / No / Maybe
```

## Attribution corrections

Attribution corrections are encouraged and treated as important.

If you believe:

- your name is missing;
- someone is incorrectly listed as an author;
- the wrong repository is identified as the original source;
- a project description is inaccurate;
- licensing information is incorrect;

please open an Issue or Pull Request.

You do not need to submit code to request a correction.

## Licensing and third-party work

Contributing something to this repository does not automatically change the license of existing third-party work.

Different components may have different licenses.

If a project's licensing status is unclear, we may keep only a reference to the original source until the situation is clarified.

When in doubt, please provide provenance rather than copying material.

## Maintainers

People who make sustained contributions may be invited to help maintain relevant parts of DS Defense.

Maintainer responsibilities may include:

- reviewing Pull Requests;
- maintaining project entries;
- helping contact original contributors;
- organizing documentation;
- resolving attribution questions;
- coordinating releases or components.

The goal is for maintainership to reflect actual participation rather than repository ownership alone.

## Code of collaboration

Please:

- respect original authorship;
- distinguish clearly between original work and derived work;
- avoid unnecessary duplication;
- keep discussions technical and constructive;
- document disagreements rather than hiding them;
- assume that attribution or licensing mistakes may be accidental and correct them transparently.

## Questions

If you are unsure how to contribute, open a GitHub Discussion.

A short message such as:

```text
I am connected to [project name] and would like to help integrate it into DS Defense.
```

is enough to start.

Thank you for helping build DS Defense.
