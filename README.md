# DS Defense

**DS Defense** is a community coordination and collaboration repository for work related to DS Defense.

This repository was created to bring together relevant projects, implementations, research, tools, documentation, and contributors that may currently be distributed across different repositories or platforms.

## Important note on authorship

The creator of this repository is acting primarily as an **initiator and coordinator**, not as the original author of all work referenced or contributed here.

Unless explicitly stated otherwise:

- Original authors retain authorship and attribution for their work.
- Existing licenses continue to apply to previously published work.
- Inclusion of a project or link in this repository does not imply transfer of ownership.
- Third-party code will not be relicensed by this repository without appropriate authorization.
- Projects with unclear licensing status may be referenced without copying their source code until their status is clarified.

If you are an original author, maintainer, or contributor to work related to DS Defense, we strongly encourage you to participate directly.

## Goals

The initial goals of DS Defense are to:

1. Identify projects and contributors working on related topics.
2. Create a shared place where relevant work can be discovered.
3. Preserve clear attribution to original authors and repositories.
4. Make it easy for original contributors to add or maintain their own work.
5. Reduce fragmentation between related implementations and research efforts.
6. Develop a community-driven structure for future collaboration.

The long-term structure of this project should be shaped by the people who actually contribute to and maintain the relevant work.

## How to participate

If you are an original author, maintainer, or contributor, you can participate in several ways.

### Add or update your project

Open a Pull Request to:

- add your repository or project;
- add documentation;
- correct attribution;
- clarify licensing;
- contribute code you are authorized to contribute;
- update an existing project entry.

### Introduce yourself

Please use GitHub Discussions to introduce yourself and tell us which part of the ecosystem you are involved with.

Suggested information:

- GitHub username;
- project or repository;
- your role;
- relevant links;
- whether you would like to maintain the project here;
- preferred way for others to collaborate with you.

### Report incorrect information

If your work is listed incorrectly, attributed incorrectly, or included in a way you are not comfortable with, please open an Issue.

Corrections and requests from original authors or maintainers will be treated as a priority.

## Contribution principles

DS Defense follows several basic principles.

### Attribution

Original authors and contributors should receive clear attribution.

### Consent

Where redistribution rights are unclear, we prefer linking to the original source rather than copying material.

### Low-friction contribution

Contributing should be simple. We want original authors to be able to add or correct information without unnecessary process.

### Distributed ownership

The project should not depend permanently on a single coordinator.

As active contributors emerge, maintainership and repository responsibilities should be shared with the people doing the work.

### Transparency

Questions about provenance, licensing, authorship, or project relationships should be documented publicly whenever possible.

## Repository structure

The repository may evolve over time, but the initial structure is expected to include:

```text
DS-Defense/
├── README.md
├── CONTRIBUTING.md
├── CONTRIBUTORS.md
├── SOURCES.md
├── LICENSE
└── .github/
    ├── ISSUE_TEMPLATE/
    └── pull_request_template.md
```

Individual projects or components may later be organized into separate directories, repositories, or organization-level projects depending on contributor preferences.

## Licensing

The license of this coordination repository does not automatically override the licenses of third-party projects.

Each contributed component must respect its original license and applicable permissions.

Where licensing information is unclear, the project should initially be referenced rather than copied.

Please include licensing information whenever submitting existing work.

DS Defense currently does not apply a single repository-wide license. Individual contributions may have different licensing or permission terms.

## For original authors and maintainers

If you found this repository because your work was referenced here:

**Thank you for creating the work that made this project possible.**

We would like you to have control over how your work is represented.

You are welcome to:

- correct the project description;
- update attribution;
- provide licensing information;
- submit the authoritative version of your work;
- maintain your component directly;
- request that we link to your repository instead of hosting a copy;
- request corrections to any inaccurate representation.

Please open an Issue, Discussion, or Pull Request.

## Governance

Governance is intentionally lightweight during the initial coordination phase.

The current repository creator is acting as the initial coordinator.

As participation grows, the goal is to establish shared maintainership among active contributors and original project maintainers.

Governance proposals are welcome through GitHub Discussions.

## Contact and coordination

For project-related communication, public GitHub Issues and Discussions are preferred whenever possible so that decisions remain visible to the community.

For sensitive matters, contributors may contact the maintainers privately using contact information published in their GitHub profiles or project documentation.
